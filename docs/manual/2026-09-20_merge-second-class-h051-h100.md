# 追記: ハイブリッド時系列履歴ドットバッジ（問題ごとの直近3回の勝敗）

- **保存**: LocalStorage `drone_question_dots` = `{問題ID:[1|0,…]}`（1=正解, 0=不正解、古い→新しい、最大3件）。`recordAnswer()` の先頭で `pushDot()` を呼び、`slice(-3)` により4回目以降は最古を押し出す。`recordAnswer()` は章別/ブートキャンプ/弱点/今日のおすすめ（回答直後）とCBT（試験終了時の採点）の両方から呼ばれるため、全モードで記録される。外部通信なし。`loadDots()` は破損データ・不正値（0/1以外）・4件超を正規化して無視/切り詰め。
- **表示**: 問題文（通常・CBT）の右上に `.q-dots`（6px の丸、間隔4px、左=古い→右=新しい）。正解=フレッシュグリーン `#6fe08a`、不正解=イエローオレンジ `#ffb454`。初見の問題は一切表示せず、表示時のみ問題文の右に余白（`.has-dots`）を確保して文字と重ならない。通常モードでは回答直後にドットが1つ増える。CBTでは出題画面に「過去の履歴」を表示し、今回の結果は終了時の採点で記録される（次回以降のドットに反映）。
- **検証（疑似DOM）**: 初見=非表示／正解→[緑]／誤答→[緑,橙]（左から右へ増加）／[緑,橙,緑]／4回目で最古が押し出され[橙,緑,橙]／再起動後にLocalStorageから100%復元／一等・二等のCBTで出題時表示・終了時記録／破損データ耐性／外部通信0件。既存の再開・見直し・グラフ検証もすべてPASS。実ブラウザでの見た目（ドットの位置・テーマ別の視認性）は未確認。

# 追記: 2-H126 の法的解釈の修正（飛行日誌の「携行」）

- **経緯**: 当初 2-H126 では飛行日誌の「携帯」を問題文から外していたが、国土交通省航空局の飛行日誌の取扱い文書に「携行」の規定があることを確認したため、携行を含む内容へ修正した。先に国交省の解説ページ（飛行日誌の作成）だけを確認して「携行の記述なし」と判断したのは確認不足だった。
- **根拠**: 国土交通省航空局 無人航空機安全課「無人航空機の飛行日誌の取扱いに関するガイドライン」（令和5年3月31日制定）および前身の「取扱要領」第4条（7）「飛行日誌の携行」＝飛行日誌を紙または電磁的記録により常時携行し、確認事項が生じた際に参照・提示できる状態にしておくこと。紙の場合は、飛行記録・日常点検記録は直近の点検整備以降の分を携行（第5条）。日誌の構成は飛行記録・日常点検記録・点検整備記録の3点。
- **修正内容**: 問題文を「航空法および国土交通省のガイドラインに基づき、作成・管理および飛行現場への「携行（携帯）」が求められている…」に、解説を携行の要点（紙/電子データ、紙の場合の携行範囲）を含む内容に更新。選択肢・正解の内容は不変。
- **表現の判断**: 飛行日誌の「作成・記載」は航空法上の義務（違反は罰則）、「携行」は国交省ガイドライン上の取扱いであるため、問題文は「法的に」ではなく「航空法および国土交通省のガイドラインに基づき」とした。
- **正解位置**: 均等化済みの配置（A=13/B=13/C=12/D=12）を保つため、2-H126 の正解は現行の位置（C、`correct: 2`）のまま。
- **検証上の限界**: ガイドラインPDFは本環境でテキスト抽出できず（フォント埋め込みのため）、条項の引用は国交省の要領を転載したページと複数の検索結果の要約で照合した。公式PDFの原文での最終確認を推奨。
